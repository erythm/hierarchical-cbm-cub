بخش اول

یک نگاه کلی

هدف این پروژه طراحی مدلی هست که نه فقط پیش‌بینی می‌کنه، بلکه توضیح می‌ده چرا — و این توضیح رو در چند سطح از کلی به جزئی ارائه می‌ده.

مثال: وقتی مدل می‌گه «این عکس گنجشکه»، باید بتونه بگه:

سطح کلی: سر ✅ بدن ✅ بال ✅ پا ✅ سطح جزئی: منقار_کوچیک ✅ بال_قهوه‌ای ✅ چشم_گرد ✅ نتیجه: → گنجشک 🐦
💡
این رویکرد در ادبیات XAI به explainable-by-design معروفه — برخلاف post-hoc methods که بعد از training توضیح می‌دن، اینجا interpretability در معماری مدل جاسازی شده.

انتخاب‌های نهایی

Dataset: CUB-200-2011

چرا این dataset؟

  • مثال beak → head که پروفسور در توضیحات پروژه آورده دقیقاً از همین حوزه‌ست
  • سه نوع annotation آماده داره که به سه بخش مدل ما map می‌شن
  • standard benchmark برای CBM papers — در مقاله اصلی Koh et al. 2020 هم استفاده شده
نوع Annotation جزئیات استفاده در مدل
312 Binary Attributes has_bill_shape::dagger, has_wing_color::brown, ... Concept Layer 2 — Fine
Part Locations مختصات + visibility flag برای سر، منقار، بال، دم، پا فقط visibility masking در loss
Class Labels 200 گونه پرنده خروجی نهایی
⚠️
نکته مهم: Part Locations فقط presence indicator هستن (این part در تصویر دیده می‌شه یا نه)، نه concept. Concept Layer 1 رو از parsing نام attribute‌ها می‌سازیم، نه از Part Locations.

از سه direction ممکن در توضیحات استاد، Direction 1 رو انتخاب کردیم:

Multi-level Explanation در بخش Evaluation پوشش می‌دیم

Research Gaps

سه gap که استاد در project description تعریف کرده. هر سه رو در literature review توضیح می‌دیم، ولی implementation فقط روی Gap 1 تمرکز داره.

Gap 1 مفاهیم Flat هستن — ما اینجا کار می‌کنیم

مدل‌های CBM فعلی مفاهیم رو بدون رابطه‌ای با هم ذخیره می‌کنن:

CBM فعلی: [منقار_کوچیک | بال_قهوه‌ای | سر | چشم_گرد | پا] → گنجشک ↑ همه هم‌سطح، بدون رابطه

درحالی‌که منقار_کوچیک زیرمجموعه‌ی سر هست. راه‌حل ما: دو Concept Layer سلسله‌مراتبی.

Gap 2 Prediction از Hierarchy استفاده نمی‌کنه

هیچ constraint ای وجود نداره که بگه «اگه سر تشخیص داده نشد، منقار هم نمی‌تونه تشخیص داده بشه». ما این رو از طریق Masked Fine Head و Consistency Loss address می‌کنیم.

Gap 3 Evaluation سلسله‌مراتبی نیست

اشتباه گرفتن گنجشک با کبوتر با اشتباه گرفتن گنجشک با کروکودیل یکسان نیست، ولی متریک‌های فعلی هر دو رو به یه شکل می‌شمارن. ما این رو در Evaluation با Hierarchical Distance metric پوشش می‌دیم.

📷 ورودی

عکس پرنده — ورودی مدل

ResNet-50 — Pretrained Backbone

آخرین FC layer حذف شده. خروجی: Feature Map F با ابعاد [2048]. این بخش دست نمی‌زنیم — فقط fine-tune می‌کنیم.

Output: F ∈ ℝ^2048 Pretrained: ImageNet

Coarse Head g_c(F) — سطح ۱

از Feature Map مفاهیم کلی (parts) رو تشخیص می‌ده.

Linear(2048→512) → ReLU → Dropout(0.3) → Linear(512→13) p_c = σ(z_c) ← 13 احتمال برای هر part
سر: 0.9 بدن: 0.8 بال: 0.85 پا: 0.7

Fine Head g_f(F, p_c) — Masked — سطح ۲

از ترکیب Feature Map و p_c ساخته می‌شه. بعد از محاسبه، Masked Fine Head اعمال می‌شه.

concat([F, p_c]) → [2048+13 = 2061] → Linear(2061→512) → ReLU → Dropout(0.3) → Linear(512→312) p_f_raw = σ(z_f) mask[i] = p_c[parent(i)] ← Masked Fine Head p_f = p_f_raw × mask ← hard constraint
bill_shape_dagger: 0.89 wing_color_brown: 0.83

🏆 Final Classifier h(p_f)

فقط از p_f می‌خونه — نه از Feature Map. این bottleneck property رو حفظ می‌کنه.

Linear(312→200) → 200 گونه پرنده

Masked Fine Head — قلب معماری

مهم‌ترین بخش معماری. فرمول:

p_f[i] = σ(z_f[i]) × p_c[parent(i)]

منطق: اگه مدل می‌گه head با احتمال 0.1 وجود داره، هیچ attribute مربوط به head نمی‌تونه احتمال بالایی داشته باشه:

حالتp_c[head]σ(z_f[bill_dagger])p_f[bill_dagger]نتیجه
Head نیست 0.1 0.9 0.9 × 0.1 = 0.09 ✅ سازگار
Head هست 0.95 0.9 0.9 × 0.95 = 0.855 ✅ قوی
✅
این یک hard constraint هست — نه فقط در training، بلکه در inference time هم اعمال می‌شه. برخلاف Consistency Loss که فقط soft penalty در training هست.

Bottleneck Property

Classifier فقط از p_f (312-dim) می‌خونه، نه از Feature Map. اگه از Feature Map هم بخونه:

  • Classifier می‌تونه concepts رو bypass کنه و مستقیم از texture و pattern یاد بگیره
  • توضیحات مبتنی بر concepts دروغ می‌شن (interpretability illusion)
  • Concept Intervention دیگه کار نمی‌کنه

Dataset Preprocessing

ساخت L1 Labels — Coarse Concepts

CUB-200 فایل attributes.txt داره با 312 خط. از parsing نام‌ها، parent هر attribute رو استخراج می‌کنیم:

# مرحله ۱ — استخراج parent از نام attribute has_bill_shape::dagger → parent: "bill" has_wing_color::brown → parent: "wing" has_eye_color::black → parent: "eye" has_crown_color::rufous → parent: "crown" # مرحله ۲ — Part categories نهایی (≈13 part) bill, wing, tail, breast, belly, leg, eye, throat, forehead, nape, crown, back, head # مرحله ۳ — L1 label برای هر تصویر L1[bill] = max(attr[bill_shape_dagger], attr[bill_shape_hooked], ...)

ساخت L2 Labels — Fine Concepts

مستقیم از image_attribute_labels.txt — با این فیلترها:

  • فقط attribute هایی که certainty ≥ 3 دارن (probably یا definitely)
  • برای attribute هایی که part مربوطه در تصویر visible نیست، loss رو mask کن

Loss Function

فرمول کلی

L_total = λ_c · L_coarse + λ_f · L_fine + λ_cls · L_task + λ_h · L_consistency

جزئیات هر Loss

L_coarse برای Concept Layer 1
L_coarse = WeightedBCE(z_c, y_coarse) pos_weight = N_negative / N_positive ← برای هر part جداگانه
L_fine برای Concept Layer 2 — Focal Loss
L_fine = FocalLoss(z_f, y_fine, α=0.25, γ=2) فقط روی attribute هایی که certainty ≥ 3 و part visible باشه # چرا Focal Loss؟ چون 312 attribute class imbalance شدید دارن: Focal Loss = -α(1-p_t)^γ · log(p_t) وقتی p_t نزدیک 1 (easy): (1-p_t)^2 ≈ 0 → loss ≈ 0 وقتی p_t نزدیک 0 (hard): (1-p_t)^2 ≈ 1 → loss بزرگ
L_task برای Final Classifier
L_task = CrossEntropy(species_logits, y_class)
L_consistency برای Hierarchy Enforcement
L_consistency = mean( max(0, p_f[child] - p_c[parent])² ) برای همه (parent, child) pairs

این penalize می‌کنه وقتی child از parent بزرگ‌تره:

حالتp_c[head]p_f[bill]penalty
سازگار0.90.80
violation کوچک0.90.95(0.05)² = 0.0025
violation بزرگ0.10.9(0.8)² = 0.64

وزن‌دهی با Uncertainty Weighting

به جای grid search دستی برای λ‌ها، از learnable uncertainty weighting استفاده می‌کنیم:

L = Σᵢ (1/2σᵢ²) · Lᵢ + log(σᵢ)

σᵢ برای هر task یک learnable parameter هست. مدل خودش یاد می‌گیره هر task چقدر وزن داشته باشه — بدون هیچ hyperparameter دستی.

Training Procedure

Optimizer

AdamW | weight_decay = 1e-4 Backbone (ResNet-50): lr = 1e-4 ← پایین‌تر، برای حفظ ImageNet features Heads و Classifier: lr = 1e-3
⚠️
چرا lr متفاوت؟ اگه backbone با lr بالا fine-tune بشه، ImageNet features از بین می‌رن (Catastrophic Forgetting). Features عمومی مثل edge detection برای تشخیص concepts ضروری هستن.

Sequential Training Phases

اگه از اول همه losses با هم فعال باشن، Classifier یاد می‌گیره concepts رو نادیده بگیره. Sequential Training جلوی این رو می‌گیره.

Phase 1a — Epochs 1–15
Backbone FROZEN
فقط L_coarse فعال. مدل یاد می‌گیره parts رو از Feature Map تشخیص بده.
Phase 1b — Epochs 16–30
Backbone FROZEN
L_coarse + L_fine + L_consistency فعال. Fine concepts روی Coarse ثابت می‌شن.
Phase 2 — Epochs 31–60
همه Unfreeze
L_task با warm-up اضافه می‌شه: λ_task(t) = (t-30)/30
Phase 3 — Epochs 61–100
Fine-tuning نهایی
همه losses فعال. Uncertainty Weighting λ‌ها رو تنظیم می‌کنه.

Hyperparameters

Batch size: 32 Epochs: 100 (با early stopping — patience=15 روی val_loss) LR Schedule: Cosine Annealing یا ReduceLROnPlateau (patience=5, factor=0.5)

💡
چرا AUROC بهتر از Accuracy برای Concepts؟ یک classifier که «همیشه negative» بگه، 98٪ accuracy می‌گیره ولی AUROC = 0.5. AUROC کیفیت ranking رو می‌سنجه و threshold-independent هست.

Concept Intervention — Gold Standard

مهم‌ترین متریک CBM evaluation. ثابت می‌کنه concepts واقعاً معنی‌دارن.

روش:

  • مدل concepts رو predict می‌کنه (مثل معمول)
  • درصدی از concepts رو با ground-truth جایگزین کن (inject)
  • Classifier رو روی concepts اصلاح‌شده اجرا کن
  • Accuracy رو اندازه بگیر

Intervention rates: 0٪, 25٪, 50٪, 75٪, 100٪

Accuracy 100% │ ╱── ✅ Concepts معنی‌دارن (slope تند) │ ╱ │ ╱ 75% │ ╱────── ⚠️ متوسط │ ╱─────────────── ❌ Concepts بی‌معنی (flat) └─────────────────→ Intervention Rate 0% 25% 50% 75% 100%
⭐
Bonus برای Hierarchical CBM: Intervention رو جداگانه روی L1 و L2 انجام بده تا نشون بدی hierarchy کار می‌کنه — اگر intervention روی L1، L2 رو هم اصلاح کنه (به خاطر mask)، یعنی hierarchy موثر بوده.

از taxonomy biological (NABirds) استفاده می‌کنیم:

Aves → Order → Family → Genus → Species

Error Localization

برای هر misclassification، تشخیص بده اشتباه از کجا اومده:

  • L1-failure: parts درست تشخیص داده نشدن
  • L2-failure: fine attributes غلط بودن (با وجود parts درست)
  • Both: هر دو سطح مشکل داشتن

خلاصه مفاهیم کلیدی

CBM
مدلی که prediction رو از طریق concepts انجام می‌ده — نه مستقیم از features. همه اطلاعات از bottleneck concepts عبور می‌کنن.
Bottleneck Property
Classifier فقط از concepts می‌خونه، نه از Feature Map. بدون این property، توضیحات concepts قابل اعتماد نیستن.
Masked Fine Head
p_f[i] = σ(z_f[i]) × p_c[parent(i)] — child نمی‌تونه از parent بزرگ‌تر باشه. Hard constraint در معماری.
is-a Relation
رابطه سلسله‌مراتبی: bill is-a part of head. این رابطه رو از parsing attribute names در CUB می‌سازیم.
Focal Loss
-(1-p_t)^γ log(p_t) — روی examples سخت focus می‌کنه. برای class imbalance شدید در 312 attribute. پیشنهاد: α=0.25, γ=2
Consistency Loss
max(0, p_child - p_parent)² — soft constraint برای hierarchy. فقط در training اعمال می‌شه (برخلاف Masked Head که hard constraint هست).
Uncertainty Weighting
Σ (1/2σ²)Lᵢ + log(σ) — λ‌های learnable به جای grid search. مدل خودش وزن هر task رو یاد می‌گیره.
Concept Intervention
inject کردن ground-truth concepts در test time. اگه accuracy بره بالا، concepts معنی‌دارن. Gold standard evaluation برای CBMs.
LCA
Lowest Common Ancestor در taxonomy درخت. برای سنجش شدت اشتباه — اشتباه گرفتن گونه‌های نزدیک بهتر از گونه‌های دور است.
AUROC
Threshold-independent metric. برای ارزیابی concept quality بهتر از accuracy — robust به class imbalance.
Sequential Training
اول concepts یاد بگیر، بعد task. جلوی bypass شدن concepts رو می‌گیره. اگه همه losses از اول فعال باشن، classifier concepts رو نادیده می‌گیره.
Catastrophic Forgetting
از دست رفتن ImageNet features در fine-tuning با lr بالا. راه‌حل: lr پایین‌تر برای backbone (1e-4) + Gradual Unfreezing.
